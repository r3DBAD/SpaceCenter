# 6. Аудит собственного кода

Методика — как на занятии №2 при разборе чужого проекта: ручной просмотр кода по чек-листу
(валидация в Model, принципы ООП, уязвимости, читаемость), запуск тестов с попытками обхода
интерфейса (вызов сервисов Model напрямую), генерация документации pdoc (выявляет расхождения
аннотаций и структуры).

## 6.1. Чек-лист

| Проверка | Результат |
|---|---|
| Валидация на уровне Model, а не только во View | ✅ Все сущности проверяют поля в конструкторах (`validation.py`); тесты `test_model.py` создают сущности с отрицательными/пустыми значениями напрямую — получают `ValidationError`. View только разбирает формат числа/даты |
| Права доступа проверяются в Model | ✅ Каждый метод сервиса вызывает `Session.require`; тест `AccessTest` вызывает сервисы в обход меню — `AccessDeniedError` |
| SQL-инъекции | ✅ Все значения передаются параметрами `?`; тесты `test_sql_injection_in_login`, `test_sql_injection_in_text_fields`. ⚠️ Имена таблиц в `_next_no` подставляются f-строкой (см. №2) |
| Хранение чувствительных данных | ✅ Пароли — PBKDF2-HMAC-SHA256, 200 000 итераций, соль 16 байт, сравнение `hmac.compare_digest`; `Staff.__repr__` не выводит хеш. ⚠️ Файл БД создаётся с правами по умолчанию (№6) |
| Инкапсуляция | ✅ Поля сущностей закрыты, только свойства для чтения; изменение состояния — методами с проверкой инвариантов |
| Глубина наследования | ✅ Не более 2 уровней (`Entity → Launch`, `PreparationStage → FuelingStage`) |
| Единая ответственность | ✅ `Launch` отвечает только за статусы и окно; проверки этапов — `stages.py`; расчёт загрузки площадки — `LaunchPad.state()` + `LaunchPadRepository.usage()`; отчёты — отдельные классы |
| Дублирование логики между слоями | ✅ Бизнес-правила только в Model; Controller не дублирует проверки. ⚠️ Дублирование вывода таблиц в контроллерах (№10) |
| Читаемость, стандарты оформления | ✅ PEP 8, docstring у модулей и публичных классов, сообщения об ошибках на русском. ⚠️ см. №1, №9 |

## 6.2. Выявленные проблемы и решения

| № | Категория | Локация | Проблема | Потенциальное влияние | Решение | Статус |
|---|---|---|---|---|---|---|
| 1 | Читаемость / корректность | `repositories.py`: `StaffRepository.list`, `LaunchPadRepository.list`, `LaunchRepository.list`, `VehicleTypeRepository.list` | метод `list()` в теле класса перекрывает встроенный `list`; аннотации ниже (`-> list[dict]`) вычисляются как обращение к методу — выявлено предупреждениями pdoc | ошибки при вычислении аннотаций (`typing.get_type_hints`), путаница при чтении | переименовать в `list_all()` | открыто |
| 2 | Безопасность (SQL) | `Repository._next_no` | имена таблицы/колонок подставляются в SQL f-строкой | сейчас вызывается только с константами, но при повторном использовании с внешними данными — SQL-инъекция | белый список допустимых троек (таблица, колонка, родитель) с проверкой перед запросом | открыто |
| 3 | Бизнес-правило | `Launch.complete` | результат пуска можно зафиксировать в любой момент после открытия окна, в т. ч. после его закрытия | «пуск» вне стартового окна — нарушение регламента, искажение отчётов | запрет фиксации после `window.end` — требуется перенос | открыто |
| 4 | Бизнес-правило | `FuelService.refuel` | не проверяется состояние площадки: если во время заправки площадку пометили неисправной, заправка продолжается | заправка на неисправном стартовом комплексе | проверка `pad.ensure_operational()` перед списанием | открыто |
| 5 | Безопасность (доступ) | `AuthService` | блокировка после 5 ошибок бессрочная (до перезапуска): злоумышленник может заблокировать руководителя, введя неверный пароль 5 раз | отказ в обслуживании для конкретного пользователя | блокировка на 15 минут по часам сервиса; счётчик сбрасывается по истечении | открыто |
| 6 | Безопасность (данные) | `Database.__init__` | файл БД создаётся с правами по умолчанию (обычно `644`) — читается другими пользователями ОС | доступ к ФИО сотрудников, хешам паролей, данным пусков | при создании нового файла выставлять права `600` | открыто |
| 7 | Производительность | `LaunchesByVehicleReport.build` | N+1 запросов: для каждого переноса отдельно загружаются пуск и тип РН | замедление отчёта при большом журнале | один агрегирующий запрос с JOIN `postponements_by_vehicle()` | открыто |
| 8 | Обработка ввода | `TelemetryController.register_incident` | нечисловой номер канала молча трактуется как «канал не определён» | ошибка оператора скрывается, НС сохраняется без канала | показывать ошибку и не сохранять запись | открыто |
| 9 | Читаемость | `ConsoleView.ask_date / ask_datetime` | значение по умолчанию переводится в строку и обратно, лишние ветвления `isinstance` | сложность сопровождения | передавать в `_ask` уже готовое значение по умолчанию | открыто |
| 10 | Дублирование | `LaunchController.register`, `PadController.list_pads` | две разные реализации вывода таблицы площадок | расхождение форматов при изменении | общий помощник `BaseController.show_pads()` | открыто |
| 11 | Демо-данные | `seed.py` | у демо-пользователей одинаковый известный пароль | при использовании демо-базы как рабочей — полный доступ посторонних | `--demo` не перезаписывает существующий файл; предупреждение в README и docstring; рабочая база создаётся только через `--init` с проверкой стойкости пароля | принято (демо) |
